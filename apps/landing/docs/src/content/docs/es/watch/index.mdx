**karajan-watch** es el vigía de la familia Karajan: un RAG compartido
sobre TODOS los repos de tu organización, alimentado en cada merge — y,
encima de él, dos respuestas que ninguna vista de un solo repo puede
darte: *¿qué otros repos puede romper este cambio?* y *¿qué
documentación acaba de quedarse desactualizada?*

## Tres capas, estrictamente separadas

| Capa | Qué es | Dónde |
|---|---|---|
| **Motor** | [karajan-rag](/docs/es/karagan/) — index/query/serve, estrategias de contexto, sensitivity policy + redacción PII | Open source, npm |
| **Producto** | **karajan-watch** — orquestación genérica: workflows reusables de ingesta, impacto y deriva. No conoce a ninguna organización. | Open source, npm |
| **Despliegue** | Un repo privado por organización: lista de repos, umbrales, infra, credenciales, golden set de calibración | Tuyo |

La dependencia apunta siempre hacia arriba — el producto nunca sabe
quién lo despliega. Como nginx y tu `nginx.conf`: el producto es de
todos, la instancia es tuya.

## Honesto por diseño

El análisis de impacto produce un **ranking de riesgo con evidencia** —
similitud del retrieval, historial de co-cambios git, coincidencias
literales de contratos (rutas HTTP, topics de evento, tablas SQL) y un
veredicto LLM gobernado por la policy. Nunca se vende como una
"probabilidad" calibrada: las heurísticas se etiquetan como heurísticas,
los contratos como evidencia, y los umbrales se calibran contra un
golden set de tus incidentes reales.
