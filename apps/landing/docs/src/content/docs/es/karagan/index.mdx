**karajan-rag** (kaRAGan) es el motor de contexto de la familia Karajan:
indexa una base de código, documentos o datos con un comando y decide —
con datos, no con fe — qué contexto viaja al modelo. Todo pasa por el
mismo camino guardado: sensitivity policy y redacción PII en cada salida
hacia un LLM.

```bash
npm install -g karajan-rag
karajan-rag index ./mi-proyecto
karajan-rag query "¿cómo se calcula la facturación?" ./mi-proyecto
```

<CardGrid stagger>
  <Card title="Un motor de estrategias de contexto" icon="setting">
    No solo retrieval: `rag` (top-k chunks), `cag` (corpus completo,
    amigable con el prompt-cache) e `hybrid` (ficheros completos
    elegidos por el retrieval) sobre el mismo índice — y
    `eval --compare-modes` para elegir con números.
  </Card>
  <Card title="Sensitivity first" icon="seti:lock">
    `public` / `internal` / `confidential` por corpus o prefijo de ruta.
    La policy enruta cada llamada LLM; `redactPII` actúa en profundidad.
    Auditado de punta a punta — el histórico de revisión independiente
    está [publicado íntegro](https://github.com/manufosela/karajan-rag/tree/main/docs/security/reviews).
  </Card>
  <Card title="Sírvelo donde quieras" icon="rocket">
    Servidor MCP para agentes, HTTP API con playground web
    autocontenido, o embébelo con `createRag()` — el mismo `RagService`
    por debajo, del portátil a Cloud Run.
  </Card>
  <Card title="Sin fallbacks silenciosos" icon="warning">
    Peer ausente, config inválida o espacio vectorial incompatible
    fallan ruidosamente con el arreglo exacto. El flujo local es
    determinista: sin credenciales ni red.
  </Card>
</CardGrid>
