Karajan Code funciona también como **servidor MCP** dentro de tu agente de IA. El trabajo lo hace tu agente; a través del servidor llega a la memoria del proyecto (`kj_rag_query`), al board (`kj_hu`) y al coder declarado en tu panel (`kj_code`) sin salir de la conversación.

## En la práctica, desde tu agente

Una de esas herramientas MCP es la memoria del proyecto: `kj_rag_query`. Antes de suponer qué hace el código, tu agente puede preguntarle al índice, y obtener una respuesta anclada en tu código, tus documentos y tus planes reales, no una adivinanza. Una **política de sensibilidad** decide qué modelo puede ver qué, y los secretos quedan excluidos del índice, así que la memoria ayuda sin filtrar nada. Tú no ejecutas nada: la herramienta está ahí en la sesión, y un buen agente la usa en vez de hacer grep a ciegas.

## Bajo el capó, pruébalo tú mismo

Esa misma memoria es un CLI, así que puedes consultarla directamente:

```sh
kj rag index                       # construye (o refresca) el índice de este repo
kj rag query "¿dónde se define la stage de pre-loop?"   # una respuesta anclada, con fuentes
kj rag query "¿cómo se calcula la facturación?" --where source~=src/billing   # sin salir de una carpeta o módulo
```

`--where` admite pares `clave=valor` unidos por `AND` (`symbol=loadConfig`, `hu_id=HU-003 AND kind=plan`) y, desde 4.63, `clave~=prefijo`: `source~=src/billing` mantiene la respuesta dentro de esa carpeta, relativa al proyecto. La recuperación híbrida fusiona la lista semántica y la léxica por rango recíproco (`rag.search.rrf_k`, 60 por defecto); el antiguo peso `alpha` ya no aplica. Un cross-encoder puede reordenar el top 40 antes de cortar el top K (`--rerank`, o `rag.search.rerank.enabled: true` en `kj.config.yml`; requiere `@huggingface/transformers`): desactivado por defecto, porque en el corpus fijo mantuvo el mismo MRR y dobló la latencia p95.

Los documentos largos se leen por índice, no enteros: `kj doc index <fichero>` lista los títulos de un markdown y `kj doc section <fichero> "<título>"` imprime una sección exactamente como está en el fichero. Por encima de `docs.indexFirstBytes` (12 000 caracteres por defecto), un fichero de tarea o un ADR llega a los roles como sus títulos más ese comando, así que el prompt lleva solo lo que la tarea necesita.

Reindexa tras un cambio (`kj rag index --since <ref>`) y las respuestas siguen al código. Nada sensible se embebe, el índice se construye con la política de sensibilidad aplicada.

## Auto-registro

Tras `npm install -g karajan-code`, el servidor MCP se **registra automáticamente** en Claude Code y Codex. No requiere configuración manual.

El hook de postinstall escribe la configuración del servidor en:

- **Claude Code**: `~/.claude.json` bajo `mcpServers`
- **Codex**: `~/.codex/config.toml` bajo `mcp_servers`

El registro es idempotente, se puede ejecutar múltiples veces sin problemas.

### Tras actualizar: `Transport closed`

Si actualizas Karajan Code mientras la sesion de tu host MCP sigue abierta, el proceso actual de `karajan-mcp` puede cerrarse y el host mostrar `Transport closed`.

Esto es esperado: desde v1.57.0, Karajan MCP realiza un reinicio graceful tras actualizaciones npm. El servidor escribe un marcador de reinicio y sale limpiamente. La nueva instancia detecta el marcador y arranca con codigo fresco.

Recuperación rápida:

1. Reinicia la sesión del host MCP (Claude/Codex).
2. Confirma que el servidor aparece listado (`codex mcp list` o equivalente en tu host).
3. Ejecuta `kj_config` antes de tareas largas.

## Configuración manual

Si el auto-registro no funciona o necesitas rutas personalizadas:

<Tabs>
<TabItem label="Claude Code">

Añadir a `~/.claude.json`:

```json
{
  "mcpServers": {
    "karajan-mcp": {
      "type": "stdio",
      "command": "karajan-mcp"
    }
  }
}
```

</TabItem>
<TabItem label="Codex">

Añadir a `~/.codex/config.toml`:

```toml
[mcp_servers."karajan-mcp"]
command = "karajan-mcp"
```

</TabItem>
<TabItem label="Host MCP custom">

Iniciar el servidor vía stdio:

```bash
karajan-mcp
```

O con una ruta explícita:

```bash
node /path/to/karajan-code/src/mcp/server.js
```

</TabItem>
</Tabs>

## Herramientas disponibles

Karajan Code expone **17 herramientas MCP**:

| Herramienta | Params requeridos | Descripción |
|-------------|------------------|-------------|
| `kj_rag_query` | `text` | Búsqueda semántica en el código, los planes y el brief de onboarding del proyecto |
| `kj_rag_index` | — | (Re)indexar el proyecto en el almacén vectorial local |
| `kj_hu` | `action` | Gestionar historias de usuario (crear, actualizar, listar, obtener) en el HU Board |
| `kj_board` | `action` | Start/stop/status del dashboard HU Board |
| `kj_code` | `task` | Que escriba el cambio el coder declarado en tu panel |
| `kj_preflight` | `humanResponse` | El humano confirma la config de agentes antes del primer `kj_code` |
| `kj_discover` | `task` | Detección de huecos antes de empezar (gaps, momtest, wendel, classify, jtbd) |
| `kj_audit` | — | Análisis de salud del código, solo lectura |
| `kj_scan` | — | Ejecutar escaneo SonarQube en el proyecto actual |
| `kj_suggest` | `observation` | Proponer una observación a Solomon |
| `kj_agents` | — | Listar o cambiar el agente IA de cada rol |
| `kj_roles` | — | Listar roles o mostrar sus plantillas |
| `kj_report` | — | Leer informes de sesión |
| `kj_init` | — | Inicializar config, reglas de revisión y SonarQube |
| `kj_doctor` | — | Verificar dependencias del sistema y CLIs de agentes |
| `kj_config` | — | Mostrar configuración actual |
| `kj_clean` | — | Limpiar estado antiguo de Karajan (en seco por defecto) |

### Retiradas en la 5.0

`kj_run`, `kj_resume`, `kj_plan`, `kj_status`, `kj_undo`, `kj_review`, `kj_triage`, `kj_researcher` y `kj_architect` movían el pipeline antiguo y se retiraron con él. Una llamada responde con un aviso y no arranca nada. Qué sustituye a cada una: [Migrar a la 5.0](/docs/es/v4/migration/).

Las skills, los comandos y los subagentes los sirve atril, no el servidor `kj` (desde la 5.0 ya no existe `kj_skills`). Para buscarlos, resolverlos, instalarlos o quitarlos por MCP, añade `atril mcp` como segundo servidor.

## MCPs complementarios

Karajan Code funciona bien junto a otros servidores MCP:

| MCP | Cómo complementa a Karajan |
|-----|---------------------------|
| [**Planning Game**](https://github.com/manufosela/planning-game-xp) | Gestión de tareas, obtener tareas, actualizar estados, seguir sprints ([servidor MCP](https://www.npmjs.com/package/planning-game-mcp)) |
| **GitHub** | Creación de PRs, gestión de issues, checks de CI/CD |
| **Chrome DevTools** | Verificación visual de cambios de UI tras la codificación |
| **SonarQube** | Acceso directo a informes de calidad (Karajan tiene SonarQube integrado, pero el MCP añade consulta directa) |

### Ejemplo de workflow con Planning Game

1. El agente obtiene la tarea de mayor prioridad desde Planning Game MCP y la pone en el board (`kj_hu`)
2. El agente consulta la memoria del proyecto (`kj_rag_query`) antes de tocar el código
3. El agente escribe el cambio con el test primero (o se lo pasa al coder del panel con `kj_code`) y pasa `kj review --staged` antes de cada commit
4. El agente crea una PR vía GitHub MCP
5. El agente actualiza el estado de la card a "To Validate" en Planning Game

Todo dentro de una única conversación, bajo los mismos gates.

## Solución de problemas

| Problema | Solución |
|----------|----------|
| Servidor MCP no encontrado | Ejecutar `npm install -g karajan-code` para activar auto-registro |
| Las herramientas no aparecen | Reiniciar tu agente de IA tras la instalación |
| Conexión rechazada | Verificar que el binario `karajan-mcp` está en tu PATH |
| Errores de SonarQube | Ejecutar `kj_doctor` para diagnosticar, o usar `noSonar: true` |
