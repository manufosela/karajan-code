## ¿Por qué Karajan Code?

En lugar de ejecutar un agente de IA y revisar manualmente su output, `kj` orquesta **roles especializados** — cada uno ejecutado por el agente de IA que tú elijas. El coder escribe código, los guards comprueban patrones destructivos, SonarQube lo analiza, el reviewer lo revisa, y si hay problemas, el coder recibe otra oportunidad. Los roles definen *qué* hacer; los agentes definen *quién* lo hace.

Si Karajan detecta `rtk --version` en el preflight, envuelve transparentemente cada comando soportado vía `wrapWithRtk()` y acumula bytes ahorrados por sesión con `RtkSavingsTracker`. **Opcional, opt-in al instalarlo** — no hace falta flag de config. Ver [docs de instalación](/docs/es/getting-started/installation/#opcional-instalar-rtk-para-ahorro-de-tokens).
  </Card>
  <Card title="Compatible con Squeezr — compresión de respuestas MCP" icon="random">
    [Squeezr](https://github.com/squeezr-ai/squeezr) es un proxy MCP que comprime las respuestas que el server MCP de Karajan devuelve al host (Claude Code, Cursor, etc.). Es **arquitectónicamente ortogonal a RTK**: RTK comprime *dentro* del pipeline (salida de comandos Bash); Squeezr comprime *encima* (mensajes MCP por el cable). Karajan no integra Squeezr — Squeezr vive en el transporte MCP del host — pero ambos componen limpiamente. Instalas Squeezr en la config MCP de tu host y Karajan se beneficia sin cambios.

| Guard | Devuelve `skipped` con `reason` | Comportamiento |
|---|---|---|
| `config.rag.preload.enabled` ausente/false | `disabled` | No-op silente. Estado default — opt-in. |

```yaml
rag:
  preload:
    enabled: true
    policy: auto       # auto | always | never  (default: auto)

```

- `always` — pull en cada run (back-compat con v2.24.0).

Si no, el stage persiste `ragPreload: { skipped: true, reason: 'auto:low-value' }` y el pipeline no paga retrieval en tasks triviales. El motivo del decisor también se persiste junto al conteo de hits cuando retrieval **sí** dispara — `resume` y `audit` pueden ver exactamente por qué retrieval corrió (o no) en cualquier sesión pasada.

### v3.4.0 — Prompts cache-friendly (actual)

Cierra la épica **Phase 1** (KJC-PCS-0057). Cada prompt de Karajan se divide ahora en un **bloque estable** — idéntico entre iteraciones de la misma HU y entre HUs del mismo plan, renderizado primero — y una **cola volátil** (task, plan, acceptance tests, feedback del reviewer, git diff). Los providers con prefix caching automático (OpenAI, Gemini, los enrutados por LiteLLM) aciertan sobre el prefijo literal estable; en Claude el bloque estable viaja vía `--append-system-prompt`, donde el CLI coloca sus cache breakpoints. **Sin breaking changes** — upgrade directo desde v3.3.0.

**Φ1-A..F — seis slices**: buckets stable/volatile con etiquetado explícito en `prompt-layout.js` (KJC-TSK-0527), migración del coder prompt preservando el orden volátil legacy (KJC-TSK-0528), reviewer prompt con el git diff de hasta 12KB como sección final (KJC-TSK-0529), system-prompt split de ClaudeAgent con rollback implícito si el rol no provee buckets (KJC-TSK-0530), migraciones de architect/HU-reviewer/ReviewerRole (KJC-TSK-0531), y suite de regresión prefix-stability que asserta bloques estables byte-idénticos y el mínimo de 1024 tokens del caching de OpenAI (KJC-TSK-0532).
