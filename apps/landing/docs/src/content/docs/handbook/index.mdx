The **Handbook** is the long-form companion to the [CLI reference](../reference/cli/). The reference is the quick lookup ("what does `--enable-tester` do?"); the handbook is the deep dive ("when does enabling the tester role actually pay off, when is it overkill, and how does it interact with TDD methodology?").

Every page follows the same canonical structure so you always know where to find the bit you need:

- **What it does** — detailed behaviour, in plain prose.
- **When to use** — concrete scenarios where the command/role/option pays off, each with a one-line example.
- **When NOT to use** — scenarios where it's overhead, noise, or a footgun, with the reason why.
- **Options** — every flag with default, when to flip it, and how it interacts with the rest.
- **Examples** — 3-5 representative recipes (typical use, CI/automation, advanced).
- **How it works internally** — 2-3 paragraphs of reasoning for users who want the "why behind the why".
- **Related** — links to the rest of the handbook.

## Where to start

If you've never used Karajan before, start at **[Install (v4)](/docs/v4/install/)** — your agent drives kj there. This handbook covers the v3 headless pipeline in depth; come here when you run `kj` directly (CI, automation, `kj advanced` commands) and want the reasoning behind each option.

From there, what you read depends on what you're trying to do:

| Goal | Start here |
| --- | --- |
| Understand `kj run` end-to-end | [`kj run`](./commands/run/) and [Pipeline roles](./pipeline-roles/) |
| Generate and execute a plan | [`kj plan`](./commands/plan/) |
| Audit a codebase | [`kj audit`](./commands/audit/) and [Audit dimensions](./audit-dimensions/) |
| Set up your environment | [`kj init`](./commands/init/) → [`kj doctor`](./commands/doctor/) → [`kj install-tools`](./commands/install-tools/) |
| Pick the right external tool | [External tools](./external-tools/) |
| Run a single role standalone | [`kj code`](./commands/code/), [`kj review`](./commands/review/), [`kj scan`](./commands/scan/), [`kj triage`](./commands/triage/) |

## Reading order suggestions

**"I want to start running real pipelines today":**
1. [`kj init`](./commands/init/)
2. [`kj doctor`](./commands/doctor/) → [`kj install-tools`](./commands/install-tools/)
3. [`kj run`](./commands/run/) — read the "What it does", skim the options, run a tiny task.
4. Come back to [Pipeline roles](./pipeline-roles/) the first time you wonder "what is `solomon` and why is it firing?"

**"I want to understand the design":**
1. [Pipeline roles](./pipeline-roles/) — the heart of the system.
2. [`kj run`](./commands/run/) → "How it works internally" section at the end.
3. [Audit dimensions](./audit-dimensions/) — what counts as a finding and why.

**"I'm setting up CI/CD automation":**
1. [`kj run`](./commands/run/) — focus on `--yes`, `--methodology`, `--max-iterations`, `--auto-pr`.
2. [`kj plan`](./commands/plan/) and [`kj audit`](./commands/audit/) — both have `--deterministic-only` flags worth knowing.
3. [`kj install-tools`](./commands/install-tools/) — `--yes --only <subset>` for non-interactive provisioning.
