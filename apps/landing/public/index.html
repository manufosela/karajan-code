The moment it says no

Your agent says the tests pass. Karajan checks.

A commit only enters with a verdict from a different AI, bound to the exact diff. Change one line and the verdict no longer matches: the commit is refused, even if the agent tries to skip the hook.

$ git commit -m "feat: retry on 429"

✕ kj: no verdict recorded for the current diff

run kj review --staged

$ kj review --staged

reviewer: codex · diff sha256:9c1e4a…

✓ approved · 0 blocking findings

$ git commit -m "feat: retry on 429"

✓ verdict matches the diff · sealed in the ledger

The method

Seven pieces, no opinions.

Mechanism where there was opinion. Evidence where there was a claim.

  1. Mandatory cross-reviewA different AI reviews every change, bound to the diff hash.
  2. Rules as mechanismNorms live in git guards and policy, not in the prompt. Security is never overridable.
  3. The SentinelBlocks the forbidden action inside the session, the moment it happens.
  4. Claims with a sourceWhat the agent states is checked against what its own session ran.
  5. Hash-chained ledgerEvery command, verdict and exception is sealed. The past cannot be rewritten unseen.
  6. Trust expiresThe Steward re-verifies the guarantees on a schedule; stale evidence stops counting.
  7. Project memoryThe agent queries the indexed code before it assumes, with secrets kept out.

And three tools it brings in

  1. atril new in 5.0Skills, commands and subagents for every AI CLI, loaded when a task needs them instead of filling the initial context.
  2. TDDThe failing test comes first, and the suite is never left red.
  3. SonarQubeStatic analysis and a quality gate on the code you change.
